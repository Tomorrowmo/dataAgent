# 工具库呈现方式重设计草图

> 目标：把「一大串看不懂的算法名」改成「我要干什么 → 它给我工具」。
> 现状代码：`web/components/AlgorithmsView.tsx`（LibraryView）+ `web/lib/algoMeta.ts`（CAT_ZH）

---

## 0. 现状（问题）

分类轴 = 算法家族（工程师内部叫法），摊成一排 pill。用户看到名词，不知道该点哪个。

```
┌─ 工具库 ──────────────────────────────────────────────┐
│ [全部 13] [滤波 5] [预处理 4] [降维 1] [回归 1] [结构 2] │  ← 一大串，看不懂
├────────────────┬──────────────────────────────────────┤
│ 巴特沃斯滤波  内置│                                      │
│ 高斯滤波      内置│        ← 选一个，右边填参数运行       │
│ 中值滤波      内置│                                      │
│ 移动平均      内置│                                      │
│ Savitzky-Golay内置│                                      │
│ 数据清洗      内置│                                      │
│ ...（继续往下滚）│                                      │
└────────────────┴──────────────────────────────────────┘
```

痛点：① 分类是「滤波/降维」这种数学名，不是用户的活；② 平铺列表越长越糊；③ 在 agent 产品里，让人「浏览工具」本身就是反的。

---

## 改法 A：换轴 —— 按「我要干什么」分组（改动最小，收益最大）

只动呈现层：把 `category` 映射到**任务意图**，列表按意图分组、每组给一句人话。

```
┌─ 工具库 ───────────────────────────────────────────────┐
│  🔍 [ 想做什么？  例：去掉温度里的尖峰…            ]      │ ← 搜索框（改法B）
├─────────────────────────┬──────────────────────────────┤
│ 🧹 准备 · 清洗            │                              │
│    数据清洗 · 缺失值填充   │                              │
│                          │                              │
│ 〰️ 平滑 · 去噪            │       ← 右侧：选中后          │
│    巴特沃斯 · 高斯 · 中值  │          填参数 + 选数据      │
│    移动平均 · SG 平滑      │          直接运行（不依赖AI）  │
│                          │                              │
│ 🎯 找特征 · 找异常        │                              │
│    异常值检测 · 插值       │                              │
│                          │                              │
│ 📈 拟合 · 建模            │                              │
│    回归拟合 · 敏感性分析   │                              │
│                          │                              │
│ 🧭 降维 · 看结构          │                              │
│    PCA · 相关性矩阵        │                              │
│                          │                              │
│ ✅ 校验                   │（暂无 → 这就是 Pillar 的缺口）│
│                          │                              │
│ 🛠️ 我自建 / AI 生成       │                              │
└─────────────────────────┴──────────────────────────────┘
```

意图分组建议（旧 category → 新意图）：

| 新分组（用户的活） | 收纳的旧 category / 算法 |
|---|---|
| 🧹 准备·清洗 | preprocess 里的 data_prep / fill_missing |
| 〰️ 平滑·去噪 | filter 全家（butterworth/gaussian/median/moving_average/savgol） |
| 🎯 找特征·找异常 | outlier_detect / interpolate / （未来 find_peaks） |
| 📈 拟合·建模 | regression / sensitivity |
| 🧭 降维·看结构 | reduce(pca) / correlation |
| ✅ 校验 | 现在是空的 —— 留这个空槽，提醒「可验证」还没成一类工具 |
| 🛠️ 自建·AI生成 | custom / source=ai|user |

> 实现：在 `algoMeta.ts` 加一张 `CAT_INTENT` 表（category→意图组），LibraryView 用 `groupBy(intent)` 渲染分段标题，不动后端。

## 改法 B：搜索 / 命令面板（更现代，配合 A）

你已经有 `aliases` 和 `examples`，天然能做「描述→工具」。把搜索框做成主入口，分组列表降级成搜索为空时的浏览态。

```
┌─ 工具库 ───────────────────────────────────────────────┐
│  🔍 [ 去掉温度尖峰_                                  ]   │
├────────────────────────────────────────────────────────┤
│  最匹配                                                  │
│   ▸ 中值滤波        去掉会拉偏均值的离群尖峰   〰️平滑去噪 │
│   ▸ 异常值检测      标记离群点(IQR/Z/Dixon)    🎯找异常  │
│  相关                                                    │
│   ▸ 高斯滤波        平滑慢变、抑制快变噪声               │
└────────────────────────────────────────────────────────┘
```

匹配来源：name + 中文名(ALGO_ZH) + example + aliases + tags。命中 example 的优先级最高（用户说的是「想要的结果」）。

## 改法 C：上下文推荐（最聪明，按数据筛）

选中数据集后，只高亮**对这份数据适用**的工具，其余折叠。判定靠列的类型。

```
当前数据：cell_42_cycle.csv  ·  列：time, voltage, temp, current
┌────────────────────────────────────────────────────────┐
│  ✨ 适用于这份数据                                        │
│   〰️ 滤波全家   （检测到时间列 → 可按采样率滤波）         │
│   🎯 异常值检测  （4 个数值列）                           │
│   🧭 相关性矩阵  （多数值列 → 可看两两相关）              │
│  ─────────────────────────────────────────────          │
│  其余工具 ⌄  （需要的列不在这份数据里，点开看全部）       │
└────────────────────────────────────────────────────────┘
```

规则示例：有时间/数值列才推滤波；≥2 数值列才推 PCA/相关；有缺失才置顶 fill_missing。

## 改法 D：归不进去的算法怎么办（关键！）

> 你的产品是**自我扩展**的——agent 不断生成新算法、专家不断发布小程序（Pillar 4）。
> 所以「归不进去」**不是边缘情况，是常态**。固定 6 个桶迟早爆。
> 原则：**tags 是真相，分组只是视图；分类法本身也要能自我扩展。**

以「多物理场数据映射（压力场→结构网格）」为例，它会分流到三种之一：

**① 孤儿暴露了意图轴缺一类** —— 最好的结果
field mapping 和已有的 `interpolate`(一维插值) 是同一件事的不同维度：都是「把数据搬到另一套坐标/网格」。
→ 意图轴该补一类 **🔀 映射·重采样·坐标变换**（interpolate 是一维婴儿版，mapping 是 3D 网格版）。

```
🔀 映射 · 重采样 · 坐标变换
   一维插值(interpolate)  ·  场映射(field_map) [多物理场]
```

**② 领域专用，不是通用原语** —— 进第二根轴「领域包」
完整 FSI 映射（带网格 + 守恒校验）不是通用积木，是 CAE 专用。不塞进通用意图轴，进领域包：

```
两根轴并存：
┌ 通用动作（意图轴） ────────────┐   ┌ 领域包（专家发布聚类）──────────┐
│ 🧹清洗 〰️平滑 🎯找特征         │   │ 📦 多物理场耦合                 │
│ 📈拟合 🧭降维 🔀映射 ✅校验     │   │    压力场→结构映射 · 守恒校验    │
│                                │   │ 📦 电池测试                     │
│ 通用原语放这边                 │   │ 📦 机器人测试                   │
└────────────────────────────────┘   │    ← Pillar 4 小程序天然成包    │
                                      └─────────────────────────────────┘
```

**③ 真的暂时无处可归**（AI 刚生成的新东西）—— 进暂存区，不是垃圾桶

```
🆕 待归类（agent 已打猜测标签：[空间映射,守恒,网格]）
   field_map_v1   ▸ 搜索仍可达 ▸ agent 建议归入「🔀映射」或「📦多物理场」
```

**自扩展机制**：生成算法时，agent 一并产出 `intent`(意图标签) + `domain`(领域包) 两个软标签；
当 ≥N 个孤儿共享同一标签 → 该标签自动升级成正式分组。分类列表像工具列表一样生长。

> 落到数据结构：给 `AlgorithmSpec` 加 `tags`（已有！）+ 复用它做多标签。
> 「分组」不进数据库，是前端按 tag 算出来的**视图**——所以加一类分组零成本。

---

## 底层观点（为什么这样改）

在 agent 原生的工具里，用户**本不该靠浏览工具列表导航**。列表存在的理由是**可验证 / 透明**（留底账），不是给人选路。

所以最终形态 = **搜索面板 + 上下文推荐当主入口，完整分组列表降级成「可信底账」**。

---

## 建议落地顺序

1. **改法 A**（意图分组）—— 半小时，纯前端，立刻不一样。
2. **改法 B**（搜索面板）—— 1~2 小时，复用现有 example/alias。
3. **改法 C**（上下文推荐）—— 之后做，需要读数据集列类型。

> 注意那个空的 **✅ 校验** 分组：它不是占位，是在提醒「可验证」目前还没沉淀成用户能点的工具——这正是产品该往里长的方向。
