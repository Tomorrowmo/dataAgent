# 技能包接入规范

技能包(Skill Pack)是**你自己写的一份工作方法**,装进 RLab Cortex 后,AI 遇到对口的活会
先读它、再按它说的做,并且能直接调用你随包带来的程序。

一个包只有两样东西:

| 你写的 | 系统怎么用 |
| --- | --- |
| `SKILL.md` —— 什么时候用这套方法、按什么顺序做、按什么判据下结论 | 命中场景时 AI 读它,把它当成高于自己默认习惯的指令 |
| `tools/`(或自带的可执行程序) —— 真正算东西的代码 | 注册成和内置算法平级的工具,AI 用 `run_tool` 调,你也能在页面上手动跑 |

---

## 1. 目录结构

```
my-skill/
├── SKILL.md            # 必需:frontmatter(身份)+ 正文(方法)
├── skill.yaml          # 可选:工具声明(也可以直接写在 frontmatter 里)
├── tools/              # 工具入口模块
│   ├── __init__.py
│   └── xxx.py          # def run(df, **params)
├── lib/                # 可选:工具共用的私有模块
│   ├── __init__.py
│   └── criteria.py
├── references/         # 可选:第三层资料,AI 按需读取
│   └── 判据来源.md
└── assets/             # 可选:工具要读的数据文件
```

安装方式二选一:

- 打成 `.zip` 上传(zip 里可以只有一层外壳目录,系统会自动进去);
- 或者把目录放到服务器上,在页面里填路径安装 —— **边改边装,不用反复打包**。

同一个 `slug` 再装一次就是升级,旧文件先移开、装失败自动回滚。

## 2. SKILL.md

```markdown
---
name: 电池循环健康度评估          # 必需,中文名就行
slug: battery-health              # 建议给;不给会按名字生成
version: 1.0.0
description: 一句话说清这个包是干什么的     # 必需
when_to_use: 什么数据、什么问题下该用它;顺便写清不该用它的边界
triggers: [容量衰减, SOH, 循环寿命]        # 命中用户原话时给 AI 一个提示
category: battery
requires: [openpyxl]              # 可选:你的工具要 import 的第三方库
---

# 正文:你的方法

（这里写:先确认什么 → 按什么顺序调工具 → 用什么判据下结论 → 回答里必须说什么）
```

**`description` 和 `when_to_use` 是这份文件里最重要的两行。** 系统提示里只放这两行加上
工具的一句话描述;正文只有 AI 判断"这活归它管"时才会读进去(`read_skill`)。所以:

- `description` 写"是什么",`when_to_use` 写"什么时候用、什么时候别用";
- 正文写死判据和顺序,**别写成教科书**——写成"按这个来"的作业指导书;
- 长资料(规程出处、试验统计、边界条件)放 `references/`,正文里用相对链接指过去。

### 正文写法建议(经验)

1. **先写"数据够不够判"**:缺什么就不许下结论,AI 会照做,这一条最能防止胡编。
2. **把步骤写成表**:第几步、调哪个工具、得到什么。AI 照表执行,不会漏步。
3. **判据写成唯一口径**:"A/B/C 分别是什么条件",并注明"以工具返回的 `grade` 为准"。
4. **写清回答里必须出现的内容**:结论 + 数字 + 不确定性。否则 AI 容易只报"已完成"。
5. **把例外前置**:比如"出现跳水直接判 C,不管平均值多好看"。

## 3. 声明工具(skill.yaml 或 frontmatter)

```yaml
tools:
  - name: capacity_fade                 # 包内唯一,小写下划线
    title: 容量衰减曲线
    description: 逐循环算保持率与每百圈衰减速率      # AI 选工具就看这句
    entry: tools.capacity_fade:run      # 模块路径:函数名
    returns: dataframe                  # dataframe | dict | series | scalar | markdown
    needs_data: true                    # false 时调用签名是 run(**params)
    params:
      cycle_col: { type: string, default: cycle, description: 循环号列名 }
      baseline_cycles: { type: integer, default: 5 }
      method: { type: string, enum: [linear, robust], default: linear }
    aliases: [容量保持率]                # AI 叫错名字时也能命中
    tests:                              # 强烈建议写:安装时会真的跑
      - name: 线性衰减能算出保持率
        params: { cycle_col: cycle }
        data:                            # 三选一:data / csv / file
          cycle: [1, 2, 3]
          discharge_capacity_ah: [2.0, 1.99, 1.98]
        expect:
          rows: 3
          columns: [cycle, retention_pct]
```

参数类型:`string | number | integer | boolean | array | object`。
`expect` 支持:`rows`、`min_rows`、`columns`、`keys`、`non_empty`。

**选列的参数建议加一个 `role`**:

```yaml
      cycle_col:
        type: string
        default: cycle
        role: cycle_index        # 我要的是"循环号"这个量,不是"叫 cycle 的列"
```

`role` 把参数从"我要一个叫 cycle 的列"升级成"我要循环号这个**物理量**"。用户遇到列名
对不上时(`Cyc_No`、`循环序号`),在界面上指一次,系统就记下「Cyc_No = 循环号」——之后
**任何技能包、任何数据集**再要 `cycle_index` 都自动认出来,而且这条规则默认共享给团队。
不写 `role` 也能用,那就退回按默认列名字面匹配。

工具的完整 slug 是 **`<包slug>.<工具name>`**,例如 `battery-health.capacity_fade`。

## 4. 工具代码怎么写

```python
# tools/capacity_fade.py
import pandas as pd
from lib import criteria          # 包内模块,随便 import

def run(df: pd.DataFrame, cycle_col: str = "cycle", baseline_cycles: int = 5) -> pd.DataFrame:
    if cycle_col not in df.columns:
        # 异常信息会原样给到用户和 AI —— 所以要写人话,并把真实列名带上
        raise ValueError(f"没有列 `{cycle_col}`。这份数据实际有:{'、'.join(map(str, df.columns))}")
    ...
    return out
```

约定:

- 顶层函数,签名 `run(df, **params)`;`needs_data: false` 的工具是 `run(**params)`;
- 返回 `DataFrame` → 自动落盘、可继续画图/接流水线;返回 `dict` → 原样进 AI 上下文;
- **报错要写人话**,把"实际有什么"一起说出来。这是 AI 能自愈的关键;
- 不确定性要写进返回值(比如 `extrapolated: true`),否则 AI 会把外推当实测讲。

### 能做什么、不能做什么(python 工具)

| 允许 | 不允许 |
| --- | --- |
| numpy / pandas / scipy / sklearn 等常用库;`requires` 里声明的第三方库 | 联网(requests / urllib.request / socket …) |
| `open()` 读写包内文件、`pathlib`、`os.path` | 起子进程(subprocess / multiprocessing) |
| import 包内自己的模块(`lib/`、`tools/`) | 删文件、改权限(`shutil.rmtree`、`os.remove`、`chmod`) |
| 抛异常、打印日志 | `eval` / `exec` / `importlib` / `pickle` 反序列化 |

违规在**安装时**就会被拒,并指出文件和行号 —— 不会等到运行才炸。
运行时还有第二层:独立子进程 + 墙钟超时 + 网络封锁。

只有**工具真正会走到的代码**才会拦整包:系统从每个工具的 `entry` 出发,顺着 import 算出
可达文件集。包里那些谁也没引用的脚本(常见于从别处下载的包,它们是给另一个运行时写的)
即使有违规也只是**提醒**,因为本系统没有任何路径能执行它们 —— 动态 import 本身就是禁的。

## 5. 自带可执行程序(runtime: command)

已有成熟的命令行工具、不想改写成函数时用这条路:

```yaml
tools:
  - name: column_stats
    runtime: command
    command: ["python", "bin/summarize.py", "--in", "{input_csv}", "--out", "{output}", "--params", "{params_json}"]
    output_file: output.csv        # 扩展名决定系统怎么读回结果
    returns: dataframe
```

占位符:`{input}`(parquet)、`{input_csv}`、`{output}`、`{params_json}`、`{pack}`。
你的程序只要满足三条:从 `--in` 读数据、从 `--params` 读参数、把结果写到 `--out` 并以
退出码 0 结束。写不出结果或退出码非 0,stdout/stderr 会原样回给用户。

⚠ **这条路径不受静态检查约束**,因此:服务端必须开 `SKILLS_ALLOW_COMMAND_RUNTIME=true`,
且只有管理员能安装,安装报告会标注 `trust: command`。只在程序来源可信时使用。

## 6. 安装时会做什么(安装报告里逐条可见)

| 阶段 | 做什么 | 不过会怎样 |
| --- | --- | --- |
| 取包 | 解压/拷贝,拦截目录穿越、符号链接、超大包 | 直接拒绝 |
| 读清单 | 解析 frontmatter + skill.yaml,归一化参数 | 直接拒绝,并指出该改哪一行 |
| 静态检查 | 逐个 .py 文件查上表的红线 | 直接拒绝,列出文件和行号 |
| 自检运行 | 每个工具先导入探针,再跑你声明的 tests | 装得上,但标记「自检未通过」,AI 会被告知这个包可能跑不通 |
| 落盘安装 | 装到 `data/skills/<用户>/<slug>/`,旧版本先备份 | 失败自动回滚 |
| 登记 | 写入索引,进入 AI 的工具表 | — |

**建议每个工具至少写一个 test。** 没有 test 的包只能验证"能导入",不能验证"算得对"。

## 7. AI 是怎么用它的(三层披露)

1. **一直可见**:包名、`description`、`when_to_use`、每个工具的一句话 —— 装 20 个包也不撑上下文;
2. **`read_skill`**:AI 判断这活归某个包管时,才把 SKILL.md 正文读进来,然后照着做;
3. **`read_skill(file=...)`**:正文指向的 `references/` 资料,追问细节时才读。

用户原话命中 `triggers` 时,系统会额外提示 AI"这句话像是归某个包管,先去看看"。

## 8. 网上下的通用 skill 包

**直接装,不用改一个字。** 通用 skill 包(Claude Code / 各类 agent 用的那种标准格式)长这样:

```
some-skill/
├── SKILL.md      # frontmatter 只有 name / description,正文是给 agent 的指令
├── scripts/      # 给"有 shell 的 agent"写的脚本
└── references/
```

装进来会发生这些事,全部自动:

| 它有什么 | 系统怎么接 |
| --- | --- |
| `SKILL.md` 正文 | 成为这个包的方法说明,AI 命中场景时 `read_skill` 读它 |
| 只有 `description`、没有 `when_to_use` | 自动从 description 里截出「什么时候用」那段(`Use when…` / `…时用`) |
| 没有 `triggers` | 自动从名字和描述里挖几个触发词(常见的 `甲 / 乙 / 丙` 别名串、`触发:…`) |
| `scripts/*.py` | 自动配一个 **`<包>.run_script`** 工具。SKILL.md 里写着"运行 `scripts/xxx.py --foo`"时,AI 就用它照原样执行,结果是脚本的标准输出;脚本若写出 csv/parquet 会一并读回成表格 |
| `references/*.md` | 自动登记成第三层资料,AI 按需读 |
| `allowed-tools` 等 Claude Code 专有字段 | 原样记录在清单里,不报错 |

安装报告里会写明「这是通用 skill 包」以及识别到几个脚本。

**执行脚本需要开关。** 通用包的脚本是别人写的任意代码,不做静态检查,所以要执行它,服务端
得开 `SKILLS_ALLOW_COMMAND_RUNTIME=true`。**不开也能装** —— 知识部分照常可用,只是 AI 调
`run_script` 时会被明确告知"这台服务器没开这个能力",而不是悄悄失败。

脚本运行时的边界:只能跑包内的 `.py`(路径越界直接拒),独立子进程 + 墙钟超时,工作目录是
临时目录,可以通过 `{input_csv}` / 环境变量 `SKILL_INPUT_CSV` 拿到当前数据集的一份 csv、
用 `SKILL_OUTPUT_DIR` 放产物。

**它做不到的事,会明说。** 通用包的指令里如果要求"写文件到用户仓库""开终端跑 git"这类本
系统的 AI 没有的能力,那部分就是做不到 —— 但它的判断标准、步骤、话术依然有价值,这些才是
这类包的主要内容。

**先验后装**:页面左下角「验一下 zip」/「验目录」是纯体检 —— 不写入任何文件,直接告诉你
能不能装、AI 会拿到什么(知识 / 工具 / 脚本)、哪些没通过、要改什么。拿不准的包一律先验。

装完还有第二道验证:进包详情的「工具」页,选一份数据**当场试跑一次**。列名类参数会按你选的
那份数据**自动推荐真实存在的列**;推荐不出来时会直接说"这份数据不是这个工具要的数据",
不会硬塞一个能跑但没意义的值。

列名对不上时面板上有一行「猜不出来?告诉它哪一列是什么 —— 教一次,以后都认」:指一次就
沉淀成一条列映射规则,下次换个包、换份数据也认得。**但只在这份数据真的含有那个量时才教它**;
数据里根本没有(比如质量过程数据里没有循环号),换数据才是对的 —— 硬指一列会让结论从根上错。

## 9. 一个包的三种状态(互不相干,别混起来看)

| 状态 | 谁说了算 | 勾上/通过时 | 反过来时 |
| --- | --- | --- | --- |
| **启用 / 停用** | 你,在包详情右上角 | AI 在对话里看得到它,命中场景会主动用 | **AI 完全看不到**(不在提示词、不在工具表)。包还在,页面上仍可手动试跑,随时勾回来 |
| **自检通过 / 未通过** | 安装时自动判定 | 工具能导入,声明的 tests 也跑过了 | 装得上,但 AI 会被告知「这个包自检没过,跑不通就如实说」 |
| **脚本 / 自带程序能否执行** | 服务端配置 `SKILLS_ALLOW_COMMAND_RUNTIME` | 通用包的脚本、自带 exe 才会真的执行 | 装得上、知识照常可用,只是执行时明确告知没开这个能力 |

停用是**唯一由你控制的开关**,含义只有一条:*AI 在对话里能不能看到这个包*。
重装升级不会把你的停用状态冲回启用 —— 想重新打开只能你自己勾。

## 10. 常见问题

**装完 AI 没用它?** 检查三处:包是不是「启用」状态;`when_to_use` 有没有写清适用场景;
`triggers` 有没有覆盖用户的真实说法(用他们的行话,不是术语正名)。

**AI 调工具参数老是错?** 在 `params` 里写 `description` 和 `default`,并在正文里给一个
调用示例。系统会自动纠偏常见的类型/容器错误(`"5"` → `5`,`"a"` → `["a"]`),但列名靠你写清楚。

**改了包怎么生效?** 按同一个 slug 重装即可(目录安装最快)。正在进行的对话下一轮就会读到新版本。

**能共享给同事吗?** 把目录或 zip 给他们各自安装;管理员可以把一个包设为公开,所有人可见。
