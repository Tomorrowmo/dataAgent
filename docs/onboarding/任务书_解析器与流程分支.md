## A.3 分流决策树（核心设计，照这个实现）

```
上传文件
├── .docx → python-docx
│            └── document.tables 逐个抽 → N 张表 → N 个 dataset
│                （0 张表 → 报错，见红线 3）
├── .doc  → 直接 400：「不支持旧版 .doc，请用 Word 另存为 .docx 后重传」
└── .pdf  → PyMuPDF 打开
           ├── 加密且无密码 → 400：「PDF 已加密，无法解析」
           ├── 有文字层？（前 5 页 get_text() 总字符数 > 200）
           │   ├── 有 → pdfplumber 抽表（主路径，不调 LLM）
           │   │        ├── 跨页表合并：表头完全相同的相邻页表格拼接
           │   │        ├── 页眉页脚剔除：在 ≥3 页里重复出现的相同行丢掉
           │   │        └── 抽出 0 张表 → 400（见红线 3）
           │   └── 无 → 扫描件降级路径
           │            ├── 逐页 render 成 PNG（150 dpi）
           │            ├── 复用现成的 image_parser.parse_image_to_df()
           │            ├── 无 LLM key → 400：「这是扫描件 PDF，需要视觉模型」
           │            └── 产出的 dataset description 必须写明：
           │                「⚠ 由扫描件 OCR 得到，数值请人工核对」
```

**为什么要这个决策树**：原生文本 PDF 有文字层，pdfplumber 抽出来是精确值、零成本、毫秒级；
一律扔给视觉模型是又贵又慢又会读错数字。这是本任务最重要的一个判断。

## A.4 实现要点

- `doc_parser.py` 只做「bytes/path → `List[Tuple[str, pd.DataFrame]]`」（表名 + 表），
  不碰数据库、不碰 session。参照 `_mesh_to_frames()` 的形状。
- 表名：`.docx` 用「表1/表2」或表格上方最近的一行标题文字；PDF 用「第3页-表1」。
- 列名清洗：去首尾空白、换行折成空格、空列名补 `col_1`；重名列加后缀。
- 单元格数值：去掉千分位逗号和单位后缀再尝试转数值，转不了就保持字符串。
- 全空行/全空列丢弃。
- 扫描件渲染 dpi 固定 150，不要更高（一页 300dpi 的 base64 能撑爆 token）。

# 任务 B：流程支持分支 / 循环

## B.0 背景（这段必须读懂再动手，不然一定返工）

看 [`db/models.py:148-167`](../../backend/app/db/models.py#L148-L167)，`FlowTemplate` 有两个字段：

- **`steps`** — 线性列表 `[{action, slug, params, label}, …]`，**回放实际执行的就是它**
- **`graph`** — React-Flow 的 `{nodes, edges}`，**纯粹是画布上给人看的**，回放前被拓扑排序压平成 `steps`

回放引擎在 [`api/templates.py:163`](../../backend/app/api/templates.py#L163)，核心就一句
`for i, step in enumerate(tpl.steps)`，把上一步的 DataFrame 喂给下一步。

**所以：在画布上画出分叉线条 ≠ 支持分支。** 这个任务的实质是
**把执行引擎从「跑列表」改成「跑图」**，`graph` 从装饰升格为执行的唯一真值源。

另外注意回放里已有一条重要逻辑不能弄丢：**report 节点不串流**
（统计/相关性这类把多行塌缩成几行的输出是旁支产物，不能喂给下一步，
判据见 `templates.py` 里 `is_report` 那段注释）。你的图引擎必须保留这个行为。

## B.1 交付物

| # | 文件 | 内容 |
|---|---|---|
| 1 | `backend/app/services/flow_engine.py` | 新建。图执行引擎，纯逻辑，不依赖 HTTP |
| 2 | `backend/app/api/templates.py` | `run_template` 改为调用引擎；老模板走兼容路径 |
| 3 | `backend/app/db/models.py` | `graph` 的 schema 注释更新；不加新表 |
| 4 | `web/components/FlowCanvas.tsx` | 新增 branch / loop 两种节点的编辑 UI |
| 5 | `backend/tests/test_flow_engine.py` | 见 B.5 的三个实验 |

## B.2 数据结构（照这个定，别自己发明）

`graph.nodes[]` 增加 `type` 字段，共三种：

```jsonc
// 1) 工具节点 —— 现状不变，type 缺省即 "tool"
{ "id": "n1", "type": "tool", "slug": "savgol_filter",
  "params": {"window": 11}, "label": "平滑", "position": {"x":0,"y":0} }

// 2) 分支节点 —— 一入两出，出边靠 edge.label 区分
{ "id": "n2", "type": "branch",
  "cond": { "metric": "rows", "op": ">", "value": 1000 },
  "label": "行数是否超过1000" }

// 3) 循环节点 —— 圈住一段子图反复执行
{ "id": "n3", "type": "loop",
  "body": ["n4", "n5"],                              // 循环体内的节点 id
  "until": { "metric": "col_std", "column": "x", "op": "<", "value": 0.01 },
  "max_iter": 20,                                    // 必填，硬上限 50
  "label": "平滑到标准差收敛" }
```

分支的两条出边：`{"source":"n2","target":"n6","label":"true"}` /
`{"source":"n2","target":"n7","label":"false"}`。

### 条件表达式 —— 白名单，禁止 eval

`metric` 只允许这些，别的一律拒绝（返回明确报错，不要静默当 false）：

| metric | 含义 | 需要 `column` |
|---|---|---|
| `rows` | 行数 | 否 |
| `cols` | 列数 | 否 |
| `col_max` / `col_min` / `col_mean` / `col_std` | 某列统计量 | 是 |
| `null_ratio` | 某列缺失比例 | 是 |

`op` 只允许 `> >= < <= == !=`。

**严禁使用 `eval` / `exec` 解析条件表达式** —— 这是用户可编辑的字段，等于给沙箱开后门。

## B.3 执行引擎的行为约定

1. **入口**：`run_flow(graph, df, ctx) -> FlowResult`。纯函数式，不直接读写数据库，
   落库通过回调传入，方便单测。
2. **遍历**：从入度为 0 的节点开始；每个节点执行后把输出 DataFrame 存进 `ctx[node_id]`；
   下游节点从它的上游 `ctx` 取输入。
3. **分支**：求值 `cond` → 只沿匹配的那条边继续；另一条边整条下游**不执行**。
   结果里必须记录 `branch_taken: "true"` 和求值实况（`"rows=1523 > 1000 → true"`）。
4. **循环**：重复执行 `body` 子图，每轮结束求值 `until`；满足则退出。
   - `max_iter` 必填，硬上限 50，超出立刻停并返回 `status: "max_iter_reached"`
   - **每一轮都要 emit 事件、每一轮的产物都要落成带血缘的派生数据集**
     （血缘 `label` 带轮次，如「平滑 · 第3轮」）
   - 可被用户取消；取消后已产生的中间结果保留
5. **report 不串流**：保留现有 `is_report` 判据。
6. **多入边（汇合）本期不做**：检测到某节点有 >1 条入边，直接返回明确报错
   「暂不支持多路汇合」，不要偷偷取第一条。
7. **老模板兼容**：`graph` 为空的模板，用 `steps` 合成一张线性图再跑，
   行为必须和改造前**逐字节一致**。

## B.4 前端

- branch 节点：菱形，两个 output handle 标 `是` / `否`，参数面板选 metric/op/value
- loop 节点：一个可折叠的框，框住 body 节点，显示 `最多 N 轮` 和退出条件
- 回放结果面板：走过的边高亮，没走的边灰掉；循环节点显示「实际跑了 7 轮」

## B.5 验收 —— 三个实验（**光看界面不算数**）

### 实验 A：分支真的分了吗

造一个模板：源 → branch → 一支 `savgol_filter`，另一支 `median_filter`。
**故意选这两个是因为它们产出的列名不同**（`x_sg11` vs `x_med5`）。

```
✅ 通过：走 true 支时产物只含 x_sg11，走 false 支时只含 x_med5，
        两次的血缘都指回同一个源数据集
❌ 失败：一次跑出来的产物里两种列都有  → 说明引擎还是把图压平成线性串着跑的
❌ 失败：不管条件真假都产出同一个结果
```

**这一条是整个任务的核心验收。画布上有分叉线条完全不能说明问题。**

### 实验 B：条件真的作用到数据了吗

同一个模板，喂两份行数不同的数据（800 行 / 1500 行）各回放一次。

```
✅ 通过：两次产物不同；界面上能看到「rows=1523 > 1000 → 走了降采样」
❌ 失败：两次产物相同
❌ 失败：条件求值是黑箱，用户看不到为什么走了这支
```

### 实验 C：循环不能把服务器跑挂

造一个**永远不满足退出条件**的循环模板（比如 `until: col_std < -1`）回放。

```
✅ 通过：跑满 max_iter 后停下，返回「已达最大轮次 20，未收敛」
✅ 通过：数据集页能看到 20 个带轮次标记的中间产物，血缘串成一条链
✅ 通过：跑到一半点取消能停，已产生的中间结果还在
❌ 失败：请求超时 / 内存爆掉 / 后端进程死掉
❌ 失败：循环期间界面一片安静，什么事件都不发
```

### 回归实验 D：老模板不能坏

改造前先跑一遍现有的任意 3 个模板，把返回的 JSON 存下来；改造后再跑，**逐字段对比必须一致**。

### 🚫 红线（一票否决）

1. **循环体每轮不落库、不发事件**（静默转圈）—— 本项目最不能接受的失败模式。
2. **`max_iter` 没有硬上限**，或允许用户设成无限。
3. **用 `eval`/`exec` 解析条件表达式**。
4. **`graph` 和 `steps` 各说各话** —— 改画布 → 保存 → 重新加载 → 回放，三者所见必须一致。
5. **老模板回放行为变了**（实验 D 不过）。
6. 多入边偷偷取第一条上游而不报错。
