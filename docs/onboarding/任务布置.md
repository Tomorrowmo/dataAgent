## 任务一：PDF / Word 文档解析器

**做什么**
现在系统能解析 CSV、Excel、图片、网格文件和 Tecplot，但工程报告最常见的 PDF 和 Word 完全不支持。你要在上传分流里加一条新路径：`.docx` 用 python-docx 抽出文档里的所有表格，每张表落成一个数据集（和多 sheet Excel 一样）；`.pdf` 先判断有没有文字层，有文字层的用 pdfplumber 直接抽表格，只有扫描件（没有文字层）才降级去调视觉模型，并且要在数据集描述里注明「由 OCR 得到，数值请人工核对」。跨页的同一张表要合并成一张，页眉页脚和页码不能混进数据行。解析逻辑写成独立的 `services/doc_parser.py`，只负责「文件 → 若干张表」，不碰数据库；落库复用现成的 `_persist_dataset`。不支持的 `.doc` 旧格式、加密 PDF、和压根没有表格的 PDF，都要给出中文人话报错，不能生成空数据集。

**怎么验**
你自己收集 9 个验收样本放进 `backend/tests/fixtures/docs/`：规整表格的原生 PDF、跨页表、双栏论文、带页眉页脚的、扫描件、无表格的、加密的、含两张表的 docx、旧版 doc。每个样本写一条 pytest，断言的必须是**行数、列名、以及你肉眼从原文核对过的几个单元格的值**，不能只断言「没抛异常」。验收时我会做三件事：一是跑 `pytest tests/test_doc_ingest.py` 看是否全绿；二是**把 LLM key 清空再跑一遍**，原生文本 PDF 必须照样解析成功——如果失败，说明你把所有 PDF 都扔给了视觉模型，这条不通过；三是把无表格的 PDF 传上去，必须明确报错，如果它返回成功并生成了一个空数据集，这条直接判不通过。

## 任务二：流程支持分支与循环

**做什么**
先读懂现状：流程模板在数据库里存了两个字段，`steps` 是线性列表、回放引擎实际跑的就是它，`graph` 是画布上的节点和连线、目前**纯粹是给人看的装饰**，回放前会被压平成线性 steps。所以这个任务的实质不是在画布上加两个节点，而是**把执行引擎从「跑列表」改成「跑图」**，让 graph 成为执行的唯一依据。需要新增两类节点：分支节点（一入两出，按行数、某列的均值/标准差/缺失率等白名单指标求值，只沿命中的那条边往下走）和循环节点（圈住一段子图反复执行，直到退出条件满足或达到最大轮次，最大轮次必填且硬上限 50）。条件表达式必须用白名单解析，**严禁用 eval**——那是用户可编辑的字段，等于给沙箱开后门。循环的每一轮都要发事件、每一轮的产物都要落成带轮次标记和血缘的派生数据集，不能静默转圈。现有的「报告类输出不参与后续数据流」的逻辑要保留，多路汇合本期不做但要明确报错。

**怎么验**
三个实验，光看界面不算数。第一个也是最关键的：造一个分支模板，两支分别跑 `savgol_filter` 和 `median_filter`——**故意选这两个是因为它们产出的列名不同**（`x_sg11` 和 `x_med5`），如果一次回放的产物里两种列都出现了，说明引擎还在把图压平成线性串着跑，画布上的分叉线是假的，不通过。第二个：同一个模板喂 800 行和 1500 行两份数据各跑一次，产物必须不同，且界面上要能看到「rows=1523 > 1000，走了降采样这支」这样的求值实况，条件不能是黑箱。第三个：造一个**永远不满足退出条件**的循环去跑，必须被最大轮次拦下并返回「已达 20 轮未收敛」，同时数据集页能看到 20 个带轮次标记、血缘串成一条链的中间产物——如果它把后端跑挂、超时、或者循环期间界面一片安静，不通过。另外你改造前先把现有任意 3 个模板的回放结果存下来，改造后逐字段对比必须一致，老模板不能坏。

## 任务三：算法命令行化

**做什么**
现在 25 个内置算法只能通过网页调用，做批处理和自动化都不方便。你要给它们加一层命令行入口：`python -m app.cli list` 列出所有算法，`describe <slug>` 打印参数说明，`run <slug> --in a.csv --out b.csv --param window=11` 执行单个算法，`run-flow flow.json --in a.csv --outdir ./out/` 按流程模板批量跑。关键约束是**这层只能是薄壳**——所有计算必须调现成的 `registry.execute_builtin`，你的 CLI 文件里不许出现任何一行重新实现的算法逻辑，也不许 import scipy 或 sklearn。另外要能脱离服务器和数据库独立运行，不需要 LLM key，`--in -` 和 `--out -` 支持标准输入输出以便进管道。

**怎么验**
四条命令行断言，都不开浏览器。一是把后端进程全部杀掉、清空 LLM key，跑一次 `run savgol_filter`，退出码必须是 0——依赖服务器或密钥就不通过。二是**同一份数据、同一组参数，CLI 的输出和网页端导出的 CSV 必须逐字节相同**，`diff` 有差异就说明你走了另一条代码路径，多半是把算法实现复制了一份，不通过。三是故意传非法参数（比如 savgol 的 window 小于 polyorder）和不存在的算法名，都必须**非零退出码**并在 stderr 给出说清楚是哪个参数不合法的中文提示，不能静默返回成功。四是 `cat demo.csv | python -m app.cli run normalize --in - --out - | python -m app.cli run pca --in - --out -` 这条管道必须跑通。另外我会 grep 你的 CLI 文件，看有没有 scipy/sklearn 的 import。
