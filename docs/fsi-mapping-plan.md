# FSI 场映射 · 落地计划

> 由 2026-06-05 与用户的方向确认而来。客户：**有具体的人/单位**（真燃料在）。
> 痛点：做映射难 / 不敢信 / 跨求解器搭桥——**三者都痛**。
> 求解器：Abaqus + OpenFOAM + ANSYS + 混合——**异构、跨厂商**。
> 范围（用户拍板）：**先做商业成熟解算器「输出结果」之间的映射**。

---

## 0. 范围锁定（这一刀很关键）

**做：** 拿 A 求解器已算完的**结果场**（如 Fluent 压力场）→ 映射到 B 求解器的**网格**（如 Abaqus 结构网格）→ 当结构分析的载荷。**后处理/结果层、单向、跨厂商。**

**不做：** 实时耦合 / 联合求解（preCICE / ANSYS System Coupling 的地盘，要插进求解过程）。

为什么这刀对：
- **跨厂商是商业工具最弱、最痛的地方**——每家的耦合只在自己生态里顺，ANSYS↔Abaqus、OpenFOAM↔Abaqus 是公认的缝。客户三套都用 = 这个缝天天踩。
- 结果层的数据是**文件**（网格 + 场），可解析（simparse / meshio 地盘），不碰各家求解器的运行时 API。
- 自带"可验证"：映射完算守恒误差，这是你的差异化命题，天然挂得上。

## 0.5 真实需求（课题 1.2 多专业仿真模型一致性接口转换）+ 两类需求

真课题三项（用户提供）：
- **a)** 气动力→结构强度(ABAQUS)：**表面压力数据(plt 格式)** 耦合映射
- **b)** 气动热→温度场(ABAQUS)：**表面热流密度数据(plt 格式)** 耦合映射
- **c)** ABAQUS 输入文件(**cae/inp**)解析+可视化；结果文件(**.odb**)批量解析 + **数据提取**

用户把它归成**两类需求**，正好对上：

| 类 | 是什么 | 对应 spec | 引擎 |
|---|---|---|---|
| **类 1：网格物理量映射** | 把一套网格/面上的场搬到另一套网格上（表面压力、表面热流），带守恒 | a) b) | 映射引擎 |
| **类 2：数据提取** | 沿**流线 / 切片 / 截面 / 线探针**等几何对象采样取值 | c) 的提取 + 通用后处理 | 提取引擎 |

### 统一内核（这条是脊柱）：两类共用**同一个内核**

> **「在一个网格化的场上、任意 3D 点处采样取值」** —— 这一个内核，两类需求都从它落出来：
> - **映射** = 查询点 = 目标网格的（表面）节点
> - **切片/截面** = 查询点 = 平面上的网格点
> - **线探针** = 查询点 = 线段上的点
> - **流线** = 查询点 = 矢量场积分出的路径上的点（= 内核 + 一次矢量积分）
>
> **先把这个采样内核建一次**，映射和提取都只是"换一组查询点"。建一次，得两类。

注意 a)/b) 是**表面映射**（2D 流形嵌在 3D 里），比体映射更贴 DataFrame（表面点 + 标量），但有自己的难点：两套不重合表面的匹配、法向投影、缝隙。守恒 = **总力 / 总热流必须守恒**——你 ceomath 里的 Tecplot 面积分就是这个校验。

## 1. 核心设计判断：结果层的「网格+场」就是一张 DataFrame

> 这条让"把 FSI 坐上"**第一个有用版本不需要新数据原语**。

- 在结果层，一个场 = **一堆点（或单元中心）上的值**。即 `DataFrame(x, y, z, pressure, temperature, …)`——**就是表格**。
- 对 **最近邻 / 线性(重心) / RBF** 映射：只需源点坐标+值 + 目标点坐标 → scipy 就能插。**完全在平台现有 DataFrame 轨道上。**
- 只有 **守恒映射（通量守恒）** 才需要单元连接关系（cells/faces）→ 那是后面的重活，单独一档。

→ 推论：Phase 1 用现有 Dataset(DataFrame) 就能跑通；mesh 连接关系作为**可选的扩展字段**在 Phase 2 才引入。**不要一上来建通用 mesh 引擎**（飞轮教训：别为还没到的规模修堤）。

## 2. 分阶段

> **建造顺序 = 内核优先。** 先建「任意点采样」内核（0.5 节的脊柱），两类需求都挂上去：
> - **类 2 提取（切片/线探针）是最便宜、最直观的第一个可见成果**——不需要第二套网格、不需要守恒，纯采样内核 + pyvista 现成算子。流线 = 内核 + 一次矢量积分，稍后。
> - **类 1 表面映射（a/b）是课题的头牌交付**——内核 + 目标面匹配 + 守恒校验（复用你 ceomath 的面积分）。建在内核之上。
>
> 所以 P0 用**头牌的一个最薄竖切**（一个真 plt 压力 → 一个真 ABAQUS 表面 + 守恒）证伪；提取作为复用同一内核的快速跟进。

### Phase 0 · 证伪（天级）— 先证明 parse→映射→守恒 在真数据上成立
照飞轮证伪的同款纪律：**先拿一个真 A→B 对，跑通最朴素的一条链，看产出值不值、什么会断。**
- 输入：一个真实的 源结果场 + 目标网格（理想是客户的真算例；手边可先用 SimGraph 的 OpenFOAM 算例 `case_run023` 当源做机制验证）。
- 链：解析源（cell 中心 + 场）→ 点云 DataFrame → 最近邻/线性插值到目标点 → **算守恒误差**（∑源 vs ∑目标）→ 可视化误差分布。
- 通过标准：① 两端都能解析；② 映射+守恒报告是客户会认可的东西；③ 记下真正断在哪。
- **不做平台集成。** 就是一个脚本，像 `tmp/_wedge_validation.py` 那样。

> **P0 内核机制验证已跑（2026-06-05，`tmp/_fsi_p0_kernel.py`）。** 真任务形状（两套不重合表面 + 压力场，仿课题 1.2a）、合成几何：
> 同一个采样内核驱动了 ① 映射(最近邻/RBF) + 总力守恒校验 ② 线探针提取。
> RBF 逐点近乎精确(max Δp 0.09 vs 最近邻 8.49)；两法力守恒误差都 0.47% —— **该误差来自目标网格更粗的面积分离散，不是插值**（验证层正该替用户点破这点）。
> **脊柱成立。未证的是客户价值 + 真表面的难例**（缝隙/曲率/部分重叠/法向投影）+ odb 需 Abaqus 装机。下一步要真 plt+ABAQUS 对。
> ⚠️ 注：手边 SimGraph OpenFOAM 算例是重型喷雾燃烧**体**算例（VTK 撞内存、且非表面），不适合当 FSI 测试数据。
>
> **P0 真数据验证已跑（2026-06-05，`tmp/_fsi_p0_real.py`）— [客户·航空航天] 课题 1.2b 真数据。**
> 源 `aeroheating_205.0s.dat`（Fluent ASCII Tecplot，74618 节点表面，X Y Z pe hre qw）→ 目标 `structure_coords.csv`（97517 ABAQUS 单元形心）→ 对标客户自己的 `interpolated_Rbf.dat`。
> **结果：我的 RBF 复现客户参考 qw 到中位相对误差 0.82%（最近邻 3.79%）。** 内核在真实工程数据上成立。
> 同时暴露客户工作流三个缺口（= 验证层价值）：① 2085 个重合节点令朴素 RBF 奇异崩溃，去重才跑通（鲁棒性）；② 朴素 Σqw≠守恒，真守恒需面积加权 ∫qw·dA（Phase 2，已诚实标注不当结论）；③ 一条尾巴的点我与客户 RBF 差很大（max|Δ|≈3432，corr 0.76）= 源面覆盖不到/陡梯度处**映射不可信**，客户现在对此无感知。
> **楔子钉死**：客户已会做映射（Tecplot2Struct.py / RBF 脚本），价值不在"做映射"，在他们缺的**守恒校验 + 覆盖/异常标记 + 鲁棒性** = 可验证。

### Phase 1 · 一个求解器对，端到端进平台（作为一个 skill）
把 Phase 0 封成重档 `field-mapping` skill（见 [skill-schema-proposal.md](skill-schema-proposal.md) Part 2，**这不是新设计，是执行已画的图**）：
- 输入：源 case + 目标网格 + 场名 + 方法；输出：映射后的场 + **守恒报告** + 误差可视化。
- `must_verify`: 总载荷守恒（相对误差给数值）+ 界面误差分布。
- 解析走 **simparse MCP / meshio**，不从零写。
- 选客户**最痛的那一个对**先做（按答案大概率是 结构(Abaqus) ← CFD(Fluent/OpenFOAM)）。

### Phase 2 · 跨求解器矩阵 + 方法 + 真守恒
- 加更多格式对（异构是客户现实）：每加一种格式 = 一个 **FormatAdapter**（DB 里已有这个 model = "教一次格式，记住"，本就是一根 Pillar）。
- 加 RBF / **守恒映射**（此时才引入单元连接关系 → mesh 成为平台一等扩展类型）。
- 守恒校验从"近似"升到"精确"（带面积/体积权重）。

### Phase 3 · 发布成小程序（Pillar 4 = 北极星落地）
专家（你/客户里的专家）把"CFD 结果 → 结构网格 + 守恒校验"封成小程序：非专家结构工程师**选 CFD 结果 + 选结构网格 → 拿到一个可信的、验证过的载荷**。**这就是"把专家经验装进可信容器给非专家用"在你真实领域里的兑现。**

## 4. 诚实的风险（按这次答案）

1. **解析异构仍是杆，但被存量砍短。** odb→VTU（odbparse）、plt+面积分（ceomath）已有；meshio/pyvista 覆盖 inp/VTU/CGNS。剩 Fluent `.cas/.dat`、cae 专有。**真依赖：读 .odb 必须有 abaqus python（Abaqus 装机）**——这条绕不开，要确认客户/你机器上有 Abaqus。**Phase 0 先只打通一对，别铺开。**
2. **守恒映射的数学是真重活。** 通量守恒、曲界面、缝隙/重叠——这是 Phase 2，别提前。Phase 1 用 RBF/最近邻 + 近似守恒先交付价值。
3. **燃料要真。** 客户具体了，但 Phase 0 必须拿**他们的一个真 A→B 对**，不是合成数据——否则又是为想象修堤。
