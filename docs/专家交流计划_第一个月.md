# 专家领域知识获取计划 · 第一个月

> 目标:把这位 CFD + 流程专家脑子里的经验,系统性地搬进三款产品(RLab Cortex / Mirror / Rsight),
> 变成可执行、可验证、可被非专家继承的能力。
> 节奏:每周二、周五各一次,共 4 周 8 次。起始:2026-06-23。

---

## 一、底层原则(决定了下面每一次怎么开)

1. **两层都要,别只收一层**
   - Layer 1 产品反馈(哪不好用/做不到/不敢信)→ 修工具。他会主动说。
   - Layer 2 专家心法(他**凭什么**这么判断)→ 沉淀成给非专家的能力 = 护城河。**他不会主动说,你必须追问"为什么"。**
2. **锚在失败 / 纠正 / 提问**,不做"请你把知识录进来"(几乎必败)。他改了什么、卡在哪、问了什么——那才是知识涌出处。
3. **每次必须产出可入库的东西**(列映射 / 术语 / 判据 / 参数 / 流程 / 工件),否则就是白聊。
4. **N=1 阶段:看他用 > 开会**。最高保真是录屏 + 出声思考,你闭嘴只看,重点抓"沉默放弃"。
5. **当场落库,不留"会后整理"**。会后整理 = 丢失。

---

## 二、固定节奏:周二"用",周五"沉淀"

把一周拆成"产出原料 → 提炼入库"的循环:

### 🟦 周二 · 陪用观察会(60–90 min)
- **他带一个真实任务 + 真实数据**(绝不用演示数据)来,当场用产品做。
- 你**全程旁观 + 录屏**,让他出声思考;只在他卡住时问一句「为什么这么做?」。
- 你记录三类时刻:① 他改了什么(纠正)② 他在哪犹豫/放弃(摩擦)③ 他随口说的术语/判断(心法)。
- 他随手用**应用内反馈按钮**(已上线,可粘截图+带上下文)标记当下想法。

### 🟩 周五 · 复盘沉淀会(45–60 min)
- 过这周的**反馈收件箱**(已上线)+ 你的观察记录。
- 走**固定三问**(见下),把每条纠正/术语/判据**当场晋升入库**(收件箱「晋升为映射规则」等),过信任门。
- 定**下周二他要带的真实任务**。

> **固定三问(每次复盘必走)**
> 1. 哪一步你**想做但做不到**? → 需要新工件(算法/解析器)
> 2. 哪一步它**做错了你得手动改**? → 真值 / 映射规则 / 校验
> 3. 哪一步你**不敢信它的结果**? → 解释 / 验证 UX
> ＋ Layer 2:**"你刚那个判断,脑子里在比对什么?"**

## 三、四周排期(主题递进 + 轮转三款产品)

| 周 | 主题 | 周二(用) | 周五(沉淀) | 本周产出 |
|---|---|---|---|---|
| **W1** | 列含义 / 术语<br>(主攻 RLab Cortex) | 用 RLab Cortex 跑一个他真实的后处理任务,看他要改哪些列、随口说哪些术语 | 列纠正 → `mapping_rules`;术语 → glossary 初稿 | ≥8 条映射规则 + 术语表 v0 |
| **W2** | 判断 / 判据<br>(RLab Cortex + Rsight) | 用 Rsight 翻一批真实算例 + RLab Cortex 看结果,听他判"对/不对/可信不可信",讲为什么 | 判断 → 判据候选(阈值/合理范围/好坏标准),过门升级 | ≥5 条判据 + 合理范围规则 |
| **W3** | 流程 / 参数<br>(Mirror + RLab Cortex) | 用 Mirror 走一个完整仿真执行流程 / RLab Cortex 串多步分析,记录他的"套路"和顺序 | 流程 → `flow_templates`;他改的参数 → 默认参数偏好 | 1–2 个可复用流程模板 + 参数偏好 |
| **W4** | 闭环验证<br>(三款) | **让一个非专家**(你/同事)用前三周沉淀过的产品跑同样任务,专家旁观挑错 | 月度盘点:沉淀了多少、命中多少(`hit_count`)、还缺什么;定下月方向 | 月度知识资产盘点 + 缺口清单 |

> W4 的"让非专家试跑"是关键验收:**专家知识有没有真的让非专家少求助、少出错**——这是北极星是否成立的直接证据。

## 四、要从他身上"挖"的领域知识清单(对应落地槽)

| 知识类型 | 怎么问 / 怎么抓 | 沉淀成 | 决策时回查点 |
|---|---|---|---|
| 列含义 / 术语映射 | 看他改列、随口叫法 | `mapping_rules`(已上线) | 解析 / 选列 / 出图 |
| 术语 / 概念解释 | "这块是什么意思?" | glossary(待建) | 用户看不懂时 |
| 判据 / 阈值 / 合理范围 | "这结果对吗?为什么?" | criteria(渊式) | 出结论 / 校验 |
| 默认参数 / 方法偏好 | 看他改了什么参数、为什么 | 算法 `default_params` | 建议参数时 |
| 流程 / 套路 | "你一般按什么顺序做?" | `flow_templates`(已有) | 复用流程 |
| 缺的解析格式 / 算法 | 他打不开的文件、做不了的算 | `format_adapters` / `algorithms`(已有) | 下次自动命中 |

- **你隔天扫一次收件箱**,别攒——新鲜的上下文才值钱。

## 七、怎么知道有没有效(月度指标)

- **沉淀条数**:映射规则 / 术语 / 判据 / 流程 / 工件 各多少。
- **`hit_count`**:沉淀的知识被回查命中多少次 = 真价值信号(没人命中的知识要么没用、要么没接到决策点)。
- **非专家完成度**:W4 非专家跑同样任务,求助次数 / 出错次数是否下降。

**本月 KPI(建议)**:≥20 条映射规则、≥1 套术语表、≥5 条判据、≥2 个流程模板、≥1 个"非专家能独立跑通"的任务。
