# 数据质量体检

目标：在分析之前，用平台工具把数据的质量问题查清楚，给用户一张一目了然的体检表。**只检查、不修改**——除非用户明确要求处理。

## 步骤

1. **概览**：从数据集上下文读出行数、列数和每列类型，不需要调用工具。
2. **缺失值**：从数据集上下文里每列的 n_missing 读取缺失数量，并计算占总行数的比例。
3. **重复行**：用 `data_prep` 只开启删除重复行（drop_dup=true，drop_na=false），比较处理前后的行数，差值就是完全重复的行数。
4. **数值异常**：对所有数值列运行一次 `outlier_detect`（method=iqr），从结果里被标记的行读出每列异常值的数量和位置。
5. **可疑列**（根据数据集上下文判断）：
   - 常量列：n_unique = 1，对分析没有信息量；
   - 疑似编号列：n_unique 等于行数的整数列，通常是 ID，不应参与统计；
   - 疑似类别列：取值很少的数值列，可能实际上是分类变量。
6. **输出体检表**：用一张表列出 | 列名 | 类型 | 缺失（数量/比例）| 异常值数量 | 备注 |，然后给出：
   - 总评：可以直接分析 / 建议先处理；
   - 按严重程度排列的问题清单，每条附处理建议和对应工具（缺失 → `fill_missing` 或 `data_prep`，重复 → `data_prep`，异常 → 先确认再剔除）。

## 注意

- 表里的每个数字都必须来自数据集上下文或本轮工具结果，不要估算。
- 异常值只是"统计上离群"，不等于错误数据，判断前要结合业务含义，在建议里说明这一点。
- 不要自动删除或修改数据；用户确认后再处理。
