# 分析结论报告

目标：把本次对话里的分析整理成一份可以直接发给同事或领导的报告。读者默认是工程技术人员；用户指定了读者（如管理层）时，相应调整措辞和详略。

## 步骤

1. **先确认有数**：报告要用到的数字如果本轮还没有算过，先用工具算出来（统计、拟合、异常检测等），**不要凭印象或心算写数字**。
2. **按下面的结构写**（Markdown）：
   1. **结论**：最多 3 条，每条一句话，带关键数字；
   2. **数据与方法**：用了哪个数据集（名称、行数）、经过哪些处理步骤、用了哪些工具和参数；
   3. **关键结果**：一张表，列出指标、数值，以及每个数字来自哪个工具或步骤；
   4. **图表**：用 `visualize` 画 1–2 张最能支撑结论的图，并说明图里看什么；
   5. **局限与风险**：样本量、缺失和异常值的处理方式、外推的不确定性、尚未验证的假设；
   6. **建议的下一步**：2–3 条具体行动。
3. **措辞**：明确区分"数据显示"（事实）和"可能原因"（推断），推断不要写成定论。

## 注意

- 报告里的每个数字都要能追溯到本轮的工具结果或数据集概况。
- 如果分析里用到了未经审核的 AI 生成算法，在「局限与风险」里写明。
- 不要为了报告完整而编造没有做过的分析；没做的就写进「建议的下一步」。
