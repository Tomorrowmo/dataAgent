# 改进清单-10：两份数据对比、按条件筛选、过程步数

来源：对话「两次吹风的结果一致吗？偏差集中在哪个攻角段？」里 AI 算不出 0°~12° 段的 CL 偏差。
已先修：对话记住每一轮用到的全部源数据（用户消息 meta.dataset_ids），重新打开时全部恢复。
状态：1–4 已实施（2026-11-10）；对话实测 对齐 → 筛选 → 差值 → 分箱汇总 7 步走通。另：工作台时间线合并流式片段（*_delta），对话里图片一律先作附件、由 AI 决定看图还是提取数据。

---

## 1. 新增内置算法「按条件筛选行」filter_rows
- 参数：condition，例如 `alpha_deg >= 0 and alpha_deg <= 12`，也支持 `0 <= alpha_deg <= 12`。
- 沿用「表达式计算」的安全求值（只认列名、数字、比较、and/or/not、常用函数），不用 pandas eval。
- 一行都不剩时报中文错误，并给出各数值列的范围，方便改条件。

## 2. 新增内置算法「对齐两份数据」align_datasets
- 参数：other（第二份数据的名称或编号）、on（对齐用的列，如 alpha_deg）、columns（要比较的列，可空=两边共有的列）、how（inner/outer）。
- 输出一张表：对齐列 + 每个比较列的 `列名_A`、`列名_B`。之后用「表达式计算」算差值，用分箱 + 分组汇总看分段偏差。
- 实现：参数类型新增 `dataset`。调用方在运行前按名称/编号取出这份数据（只在本人的数据里找），读成表交给算法；运行记录里仍只存名称，重跑时再取。
- 接入：对话、算法页运行 / 存为数据集、流程、重跑、运行记录复现。

## 3. AI 写算法、AI 对话的规则
- 写算法的提示词：run(df) 只收到一张表，参数只能是文字 / 数字 / 列表，不能把数据集当参数；需要两份数据时，先由调用方用 align_datasets 对齐，再在对齐后的表上计算（列如 CL_A、CL_B）。
- 对话提示词：比较两份数据的数值 → align_datasets → derived_column → bin_column + group_aggregate；取某个区间的行 → filter_rows（先对齐再筛选）。

## 4. 「过程 · N 步」计数虚高
- 现在把 AI 流式输出的每一小段文字（thought_delta）都算成一步，出现「644 步」。改为只数真正的步骤（调用模型、运行工具）。

## 验收
- 后端测试：filter_rows（正常 / 链式比较 / 全部筛掉）、align_datasets（按名称取第二份数据、列名后缀、找不到数据集的报错）、运行记录里存的是名称。
- 实际在对话里问「两次吹风只看 0°~12° 段的 CL 偏差」，AI 能走通 对齐 → 筛选 → 差值 → 分段汇总。
- 「过程」显示的步数和工作台里的步骤一致。
