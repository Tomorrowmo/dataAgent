# 改进清单-7：算法 / 技能 / 流程三个库的统一设计（含 AI）

来源：「喜欢现在的算法首页，只是信息不足；首页上直接接入 AI，再加导入和 AI 生成两个入口；算法、技能、流程都有 AI 参与的部分，要统一设计」
效果图：`pk/claude/工具库统一效果图.html`
状态：方案，确认后再改代码。

---

## 一、先把三样东西说清楚

| | 是什么 | 在对话里怎么用 | 不经过 AI 时怎么用 |
|---|---|---|---|
| **算法** | 一段处理数据的代码（平滑、FFT、拟合…） | AI 挑选并调用 | 选数据、填参数，直接运行 |
| **技能** | 一份分析规范（检测流程、判定标准、报告格式） | 在输入框上方勾选，AI 按它来分析 | 不单独运行 |
| **流程** | 几个算法按顺序串起来、参数固定的处理步骤 | 在对话中运行，结果写进对话 | 选数据，一键重跑 |

三者关系：流程由算法组成；技能约束 AI 怎么选算法、怎么写结论。

## 二、现状：AI 在三个库里各做各的

| 页面 | 现有 AI 能力 | 交互方式 |
|---|---|---|
| 算法 | 生成新算法；编辑器里「AI 改写」「AI 修这个报错」「AI 校正」；运行面板「AI 帮你填参数」 | 生成和改写都先出草稿 / 修改稿，沙箱自测，确认后保存 |
| 技能 | 详情里「AI 调整说明」 | **改动立即保存**，没有草稿 |
| 流程 | 画布节点「AI 帮你填参数」 | 没有 AI 生成流程；流程只能从对话「存为流程」或手动搭 |

问题：入口位置不一样、能做的事不一样、确认方式不一样（技能直接保存，算法要审核）。

## 三、统一的页面结构：左侧列表 + 右侧工作区

保留现在算法页的结构（你喜欢的那版），三个库都改成同一个样子：

```
┌────────────┬──────────────────────────────────────────────┐
│ 左侧列表    │ 右侧工作区                                    │
│ [搜索]      │  没选中任何一项时 → 库概览（带 AI）            │
│ 我的 (3)    │  选中一项时       → 详情（现在的详情界面）      │
│  · …待审核  │                                              │
│ 内置 / 示例  │                                              │
│  · …        │                                              │
└────────────┴──────────────────────────────────────────────┘
```

- 左侧列表：顶部搜索；分「我的」（含 AI 生成的，待审核的标黄）和「内置 / 平台默认 / 示例」两组；算法按类别再分小组。
- 右侧默认显示**库概览**，选中左侧某一项后显示**详情**；点详情里的「← 概览」或再点一次已选项，回到概览。
- 流程页：从「一进去就打开第一个流程的画布」改为先显示概览；技能页：从卡片网格改为同样的左右结构。

## 四、库概览（右侧默认内容）

从上到下五块，三个库一致，只是文字和示例不同：

1. **标题和一句话说明**
2. **两个入口**（并排两张卡片）
   - **AI 生成**：展开下面的 AI 输入框；
   - **导入**：算法 = 贴代码 / 上传 .py；技能 = 上传 .zip / SKILL.md；流程 = 从对话保存（说明怎么做）/ 复制一个示例流程。
3. **AI 输入框**（默认展开在 AI 生成入口下）：一行说明 + 文本框 + 2–3 个示例写法 + 「生成」按钮。
4. **待审核**：AI 生成、还没确认保存的草稿，每条有「审核」按钮（来自这里，也来自对话里 AI 新写的算法）。
5. **最近用过** + **库里有什么**（按类别的数量），点了跳到左侧对应位置。

## 五、AI 的统一交互：描述 → 草稿 → 检查 → 保存

三个库里的所有 AI 操作都按同一套步骤，结果永远先是草稿，不直接覆盖：

| 步骤 | 算法 | 技能 | 流程 |
|---|---|---|---|
| ① 描述 | 「按 α≤10° 取线性段拟合升力线斜率」 | 「风洞数据先做洞壁修正再算系数，结论保留三位有效数字」 | 「先平滑，再做 FFT，找前 3 个峰」 |
| ② 先查库 | 库里已有能实现的算法 → 先推荐「用现有的 / 组合现有的」，避免重复造 | 已有相近技能 → 提示「在它基础上修改」 | 优先用库里已有算法串；缺的算法列出来，可一键让 AI 补写 |
| ③ 草稿 | 代码 + 参数说明 | SKILL.md 说明文本 | 步骤链（算法 + 参数） |
| ④ 检查 | 沙箱自测（已有） | 预览说明 + 拿一份示例数据试问一次 | 在示例数据或指定数据上试运行 |
| ⑤ 保存 | 保存为新算法 / 新版本 | 保存技能 | 保存流程 |
| 标记 | 保存前在列表里显示「待审核」，保存后显示「AI 生成」来源标签 |||

**详情页里的 AI 修改**也统一：三个详情页都有同一个「AI 修改」侧栏（现在算法编辑器里的 AI 助手就是这个形态）：
- 用一句话说要改什么 → 出修改稿（标出改了哪里）→ 自测 / 预览 / 试运行 → 「应用为新版本」或「放弃」；
- 技能的「AI 调整说明」从**立即保存**改为**先出修改稿再应用**，和算法一致；
- 流程详情加上「AI 修改」：例如「把平滑窗口改成 21」「在 FFT 前加一步去趋势」。

**对话也是入口**：对话里 AI 新写的算法、「存为流程」保存的流程，都进入对应库的「待审核」，在库里统一审核。

## 六、需要新增的后端能力

| 能力 | 说明 | 现状 |
|---|---|---|
| 生成前先查库 | 根据描述在算法 / 技能库里找相近的（用大模型从库清单里挑，附理由） | 只有前端关键字匹配 |
| AI 生成技能 | 描述 → SKILL.md 草稿 | 没有，只有修改已有技能 |
| AI 生成流程 | 描述 → 用库里算法组成的步骤链草稿；列出缺的算法 | 没有 |
| 流程 AI 修改 | 一句话改步骤 / 参数 → 修改稿 | 没有 |
| 技能修改稿 | 「AI 调整说明」返回修改稿，不直接保存 | 现在直接保存 |
| 使用次数 | 「最近用过」按运行记录统计 | 运行记录已有，需要加统计接口 |

## 七、分步实施

1. 三个库统一成「左侧列表 + 右侧概览 / 详情」，概览里先放入口、待审核、最近用过（不含新 AI 能力）。
2. 算法：概览里的 AI 输入框接现有「生成算法」，加「先查库」。
3. 技能：AI 生成技能；「AI 调整说明」改为修改稿。
4. 流程：AI 生成流程（含缺失算法提示）、流程详情的 AI 修改。
5. 「最近用过」的统计接口。

每步做完都实际走一遍：生成 → 草稿 → 检查 → 保存 → 在对话或流程里用上。

## 八、需要你确认

1. 三个库都用「左侧列表 + 右侧概览 / 详情」——技能页会从卡片网格改成这个结构。
2. AI 操作一律「先草稿、确认后保存」——技能的 AI 调整会从立即保存改为先出修改稿。
3. AI 生成前「先查库」：可能会推荐用现有算法而不是新写，多一步选择。
4. 实施顺序是否按第七节。
