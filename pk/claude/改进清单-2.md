## 前提与已定事项

**前提：不保留分析历史，保留基础数据**

| 保留 | 不保留（升级时处理） |
|---|---|
| 账号、模型配置、算法（含版本历史）、流程、技能、上传的原始数据 | 旧的运行记录（`runs` 表直接重建）、共用目录 `uploads/results/` 下的文件（删除）、旧的中间结果数据集（删除行和文件） |

- 旧对话保留文字内容；旧消息里的结果卡片（引用服务器路径）显示"升级前的结果，无法预览"。
- 原始数据文件不搬家：数据集行带 `owner_id`，路径解析函数允许读取"属于本人的旧绝对路径"，新上传按新目录写。
- 旧流程的步骤没有版本信息，按"未锁定版本、使用当前版本"运行，并提示用户锁定。
- 迁移写在 `db/base.py` 启动流程里，可以重复执行；执行前自动备份 `app.db`（SQLite 用 `VACUUM INTO` 生成一致的备份）。
- **各环境负责人需要确认**：已交付的部署是否接受"旧中间结果和旧运行记录被删除"。

**已定的数字**

| 项 | 值 |
|---|---|
| 中间结果默认保留 | 创建后 20 天 |
| 到期前提醒 | 提前 3 天 |
| 未确认提醒的兜底期限 | 创建后 60 天 |
| 运行记录本身保留 | 至少 180 天 |
| 每条运行记录的数据预览 | 最多 20 行 |

**已定的取舍**
1. 没有可用模型时，"体验示例"用内置算法做确定性演示。
2. 流程不能包含"尚未确认保留"的 AI 草稿算法。
3. "在对话中运行流程"做完整版，结果作为一条消息存进会话。

## 第 2 步　对话与算法、流程连起来

**心智模型**：对话 = 探索；算法库 = 工具箱；流程 = 固化复用。

### 2.1 执行时记录真实依赖（L1、L2 的基础）

| 编号 | 改动 |
|---|---|
| E1 | 对话里每次运行算法时记录：**实际输入**（数据集编号，或本轮中某个前序步骤的编号——包括回退到更早数据帧的情况）、算法编号与版本、完整参数、**输出角色**（数据 / 报告）。输出角色用与流程相同的判定规则，并在事件里写明，避免对话和流程各判各的 |
| E2 | 流程运行改为读取步骤里保存的输入引用和输出角色，不再在运行时重新猜"是否报告" |

### 2.2 入口

| 编号 | 改动 | 验收 |
|---|---|---|
| L1 | 结果卡片的算法名可点，跳到算法库并带上 E1 记录的**实际输入、版本、参数**。输入已被清理、算法版本已变化、或算法含随机性时，跳转后明确提示"结果可能与对话不一致"及原因 | 输入与版本都在时，直接执行结果与对话一致 |
| L2 | "存为流程"入口按**成功、可保存的执行步骤**计数，≥ 2 步才显示 | — |
| L2a | **只允许保存输入依赖能完整确定的单数据源链**：每一步的输入要么是起始数据集，要么是链内前序步骤。出现以下情况直接阻止保存并说明原因：用到第二个数据集（含交叉依赖）、某步输入无法确定、依赖链外的中间结果。预览列出每步的输入引用、输出角色，以及不包含的步骤（画图、生成算法） | 存下的流程逐步回放，每步输入与原对话一致 |
| L2b | 后端资格校验：流程**创建、修改、运行**三处都检查算法存在、本人可访问、不是"未确认保留"的 AI 草稿、锁定的版本存在；界面称"已确认保留" | 绕过前端直接调接口同样被拒 |
| L2c | 回放语义：某步失败即**停止后续步骤**，整体标记"部分成功" | — |
| L2d | 流程步骤保存：`algorithm_id`、锁定版本、参数、输入引用、输出角色。运行默认使用锁定版本；算法有新版本时在流程页提示"有新版本 · 更新流程"，由用户决定是否升级 | 修改算法后，旧流程仍按锁定版本运行 |
| L3 | 算法详情加"在对话中使用"；流程页加"在对话中运行"：后端直接执行流程（不经过 AI），结果作为一条"流程运行"消息写入当前会话，刷新后仍在，后续 AI 能读到 | 刷新后结果仍在；接着提问 AI 能引用 |
| L4 | 对话欢迎页"我的流程"：选数据后按 L3 同样的方式在对话里执行 | 与 L3 行为一致 |
| L5 | 各处文案统一按心智模型写 | — |

### 2.3 版本与复现

| 编号 | 改动 |
|---|---|
| A1 | 删除算法改为**软删除**（记删除时间，从算法库隐藏），版本历史保留；引用它的流程显示"算法已删除"并禁止运行 |
| V1 | **重跑**：当前版本 + 新数据。**复现**：当时的算法版本 + 参数 + 输入。自定义/AI 算法从版本历史取当时代码；内置算法记录当时的软件版本号，版本不同时提示。**输入和算法版本都可用才允许复现**，否则按钮置灰并写明缺什么 |

## 第 3 步　运行记录、数据来源与存储

### 3.1 运行记录

| 编号 | 改动 |
|---|---|
| D1 | `runs` 表重建：所属用户；**批次编号**（`group_id`）与组内序号；入口（对话 / 算法库 / 流程页）与执行对象（单个算法 / 流程）分开记录；会话编号、流程编号；算法编号（可空）+ 算法标识 + 算法版本 + 软件版本；参数；实际输入（数据集编号或前序运行编号）；输出沿用 `result_dataset_id`，结果文件关联 `artifacts`；状态（成功 / 失败 / 取消 / 部分成功）；错误；耗时；数据预览（≤ 20 行）；创建时间。`datasets` 表新增 `run_id` |

### 3.3 保留与清理（清理策略重构）

**状态与时间规则**（适用于未保留的中间结果数据集和结果文件）

| 字段 / 规则 | 定义 |
|---|---|
| 到期时间 | 创建时 = 创建时间 + 20 天 |
| 用户延期 | 到期时间 = 操作时刻 + 20 天，可多次延期；延期后兜底期限不再适用 |
| 进入提醒 | 距到期 ≤ 3 天时出现在数据集页的"即将清理"清单 |
| 提醒确认 | 服务端按**每一项**记录确认时间：用户在清单里对该项做过任何操作（保留 / 延期 / 立即清理 / "我知道了"）才算确认。登录或打开页面不算 |
| 清理条件 | 未保留、未受保护，并且满足以下任一：① 已到期、已确认提醒、且确认后已过 24 小时；② 从未延期且创建满 60 天（兜底，无论是否确认） |
| 保留 / 受保护 | 永不自动清理 |
| 清理后 | **保留数据集行**，状态改为"已清理"，删除文件和运行记录里的数据预览；血缘树中显示为灰色"已清理"节点；运行记录保留并标注"数据已清理，无法完整复现" |

| R3 | 提醒界面：数据集页顶部提示"有 N 份中间结果将在 3 天内清理"，清单逐项显示剩余天数，可逐项或全部保留、延期、立即清理 |

| 步骤 | 必须覆盖 |
